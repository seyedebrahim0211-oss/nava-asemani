# نوای آسمانی | Nava Asemani

**«هر نوا، راهی به نور»** — اپلیکیشن اندروید فارسی، راست‌به‌چپ و واکنش‌گرا برای مداحی، روضه، سخنرانی مذهبی، ادعیه، مناجات و قرآن، همراه با سرور مدیریت محتوا و ساخت APK خودکار در GitHub Actions.

> ⚠️ این مخزن **نسخه توسعه‌ای ۰.۱.۰ (MVP)** است، نه محصول نهایی منتشرشده. سرور API و تست‌های آن با پایتون آزمایش شده‌اند؛ ساخت APK در محیط فعلی انجام نشده چون Android SDK/Gradle موجود نبود. بعد از قرار دادن مخزن در GitHub، نتیجه کامپایل واقعی در Actions مشخص می‌شود. چهار تلاوت آزمایشی با مجوز باز و پنج کارت نمایشی فاقد صدا هستند. هیچ افزونه‌ای برای برداشت غیرمجاز محتوای کآشوب یا نوا فعال نیست.

## امکانات نسخه فعلی

- کدنویسی بومی اندروید با **Kotlin + Jetpack Compose** و رابط فارسی RTL.
- شش بخش محتوایی و فیلتر دسته، جست‌وجوی کلمات در عنوان/هنرمند/موضوع/برچسب.
- پخش آنلاین و پس‌زمینه با **Media3**، کنترل پخش از اعلان سیستم و مینی‌پلیر.
- دانلود فایل‌هایی که مجوز دانلود دارند با **Android DownloadManager** و ذخیره در پوشه عمومی `Music/NavaAsemani`، پخش فایل دانلودشده در اولویت.
- علاقه‌مندی‌ها و پلی‌لیست‌های محلی، ذخیره در SharedPreferences روی همان گوشی.
- نمایش منبع و نوع مجوز هر فایل، ارجاع به صفحه اصلی.
- نسخه تبلت با NavigationRail؛ نسخه موبایل با ناوبری پایین.
- کاتالوگ JSON پیش‌فرض؛ دریافت کاتالوگ به‌روزشونده از URL امن HTTPS.
- **سرور FastAPI + SQLite + داشبورد فارسی**: درج اثر، ویرایش، بازبینی مجوز، انتشار/لغو انتشار، API عمومی.
- ابزار اختیاری کشف **فقط فراداده** RSS/Atom از منابع دارای مجوز؛ مورد کشف‌شده تا تأیید انسانی منتشر نمی‌شود.
- Workflow برای تولید Debug APK و تست سرور در GitHub Actions.

## مرحله ۱ — ساخت مخزن در GitHub (از ویندوز)

۱. وارد https://github.com/new شوید و مخزن با نام `nava-asemani` بسازید. **README یا فایل اولیه اضافه نکنید** چون این پروژه خودش فایل‌ها را دارد.

۲. ZIP پروژه را دانلود و استخراج کنید. نرم‌افزار **Git for Windows** را از https://git-scm.com/downloads/win نصب کنید.

۳. داخل پوشه استخراج‌شده، یک Terminal / Git Bash باز کنید و دستورات زیر را اجرا کنید (به‌جای `USERNAME` نام کاربری خودتان را قرار دهید):

```bash
git init
git add .
git commit -m "Initial Nava Asemani Android MVP"
git branch -M main
git remote add origin https://github.com/USERNAME/nava-asemani.git
git push -u origin main
```

برای ورود GitHub از مرورگر یا Git Credential Manager استفاده کنید؛ رمز یا توکن را داخل کد قرار ندهید.

## مرحله ۲ — دریافت APK بدون Android Studio (ساده‌ترین روش)

۱. در مخزن GitHub، تب **Actions** را باز کنید. در صورت نیاز اجرای Actions را فعال کنید.

۲. از فهرست سمت چپ **Build Android APK** را انتخاب کنید و **Run workflow** را بزنید (یا پس از `push` خودکار اجرا می‌شود).

۳. پس از **موفق‌شدن** اجرای workflow، در بخش **Artifacts** فایل `nava-asemani-debug-apk` را دانلود و از ZIP خارج کنید؛ فایل `app-debug.apk` به دست می‌آید.

۴. APK را به گوشی منتقل و نصب کنید. نصب از منابع غیرمعمول را فقط برای برنامه‌ای که خودتان ساخته‌اید فعال کنید. این فایل **Debug** است، برای تست و نصب شخصی؛ برای انتشار رسمی باید Signed Release APK/AAB ساخته شود.

۵. اگر workflow قرمز شد، لاگ مرحله **Assemble debug** را باز کنید. چون ساخت اندروید اینجا اجرا نشده، امکان وجود خطای نسخه ابزار/کامپایل باید با آن لاگ بررسی شود.

## مرحله ۳ — بازکردن سورس در Android Studio

- Android Studio نسخه جدید، **JDK 17**، **Android SDK API 36** و Gradle **8.13** لازم است. حداقل نسخه گوشی **Android 10 (API 29)** است.
- مسیر پروژه‌ای که `settings.gradle.kts` دارد را با **Open** باز کنید.
- اگر IDE گفت Gradle Wrapper کامل نیست، چون فایل رسمی `gradle-wrapper.jar` در این بسته وجود ندارد، ابتدا Gradle 8.13 را روی سیستم نصب و در ریشه پروژه اجرا کنید: `gradle wrapper --gradle-version 8.13`؛ سپس فایل‌های تولیدشده (`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`) را به مخزن اضافه کنید.
- بعد از Sync، از **Build > Build APK(s)** یا دستور `./gradlew :app:assembleDebug` استفاده کنید.
- خروجی Debug در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد.

## مرحله ۴ — اضافه‌کردن محتوای واقعی

### راه A: بدون سرور (مناسب شروع)

فایل `app/src/main/assets/catalog.json` را تغییر دهید؛ قالب:

```json
{
  "version": 1,
  "items": [
    {
      "id": "official-001",
      "title": "عنوان صوت مجاز",
      "artist": "نام مداح یا قاری",
      "category": "مداحی",
      "occasion": "محرم",
      "description": "توضیح اثر",
      "streamUrl": "https://YOUR-MEDIA-HOST/example.mp3",
      "sourceUrl": "https://YOUR-OFFICIAL-PAGE/item",
      "sourceName": "رسانه رسمی صاحب اثر",
      "license": "مجوز کتبی / نوع پروانه",
      "downloadAllowed": true,
      "tags": "شور محرم"
    }
  ]
}
```

فقط لینک‌های HTTPS و رسانه‌ای که اجازه پخش/دانلود آن را دارید اضافه کنید. پس از هر تغییر برای اعمال روی نسخه بدون سرور، APK را مجدد بسازید.

### راه B: سرور مرکزی (برای آرشیو بزرگ و به‌روزرسانی خودکار)

به یک VPS یا هاست Docker با HTTPS و دامنه نیاز دارید. **GitHub Pages به‌تنهایی سرور Python یا بانک اطلاعاتی را اجرا نمی‌کند.**

```bash
cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
# خروجی تولیدشده را در .env به جای NAVA_ADMIN_TOKEN قرار دهید
docker compose up -d --build
```

به صورت پیش‌فرض سرور فقط روی `127.0.0.1:8000` گوش می‌دهد؛ برای استفاده اینترنتی، آن را پشت Caddy/Nginx با HTTPS و محدودسازی دسترسی مدیریتی قرار دهید. پنل در `https://YOUR-API-DOMAIN/admin/` و کاتالوگ عمومی در `https://YOUR-API-DOMAIN/v1/catalog` خواهد بود. پس از راه‌اندازی، چهار نمونه دارای مجوز را می‌توانید با گزینه «ورود نمونه‌های دارای مجوز باز» اضافه کنید.

برای دریافت کاتالوگ سرور در اپ، در فایل محلی `local.properties` (کنار `settings.gradle.kts`) خط زیر را قرار دهید:

```properties
catalog.url=https://YOUR-API-DOMAIN/v1/catalog
```

سپس APK را دوباره بسازید. برای اینکه APK تولیدی GitHub Actions هم به سرور وصل شود، در GitHub از **Settings > Secrets and variables > Actions > Variables**، متغیر `NAVA_CATALOG_URL` را با همین HTTPS URL تنظیم کنید. فایل `local.properties` و کلید مدیر هرگز نباید در GitHub ذخیره شوند.

## مرحله ۵ — کشف خودکار آثار از منابع دارای مجوز

ابزار `scripts/discover.py` از **خوراک‌های رسمی RSS/Atom که اجازه خواندنشان را دارید**، *فقط عنوان و لینک صفحه* را می‌خواند؛ هیچ فایلی دریافت/بازنشر نمی‌کند. اطلاعات پیدا شده به صورت پیش‌نویس وارد پنل می‌شوند. مدیر باید رسانه، حق انتشار، منبع و مدرک مجوز را ثبت و سپس منتشر کند.

برای اجرای زمان‌بندی‌شده، در GitHub زیر **Actions secrets** این موارد را اضافه کنید:

- `NAVA_API_URL`: نشانی HTTPS سرور، مانند `https://api.example.com`
- `NAVA_ADMIN_TOKEN`: کلید محرمانه ۳۲ کاراکتری یا بلندتر سرور
- `NAVA_FEEDS_JSON`: آرایه JSON از خوراک‌های *واقعاً مجاز*، مثل `[ {"url":"https://example.org/approved.xml","source":"رسانه رسمی","category":"مداحی"} ]`

سپس زیر **Actions variables** متغیر `NAVA_DISCOVERY_ENABLED` را برابر `true` بگذارید. Workflow هر ۱۲ ساعت اجرا می‌شود. **برای کآشوب و نوا API رسمی یا مجوز بازنشر در این بسته فرض نشده است.** در صورت نبود RSS مجاز، اتصال اختصاصی باید طبق توافق با منبع ساخته شود.

## مرحله ۶ — خروجی نهایی برای انتشار عمومی

برای انتشار رسمی در مارکت‌ها باید نام بسته، لوگو، اطلاعات سیاست حفظ حریم خصوصی و مجوزهای نشر تکمیل شوند؛ سپس Signed AAB با کلید اختصاصی خودتان تهیه کنید. کلید امضا باید امن بماند و **به GitHub عمومی آپلود نشود**. همچنین آزمایش روی چند گوشی و نسخه مختلف اندروید، دسترس‌پذیری، دانلود در حالت کمبود حافظه، قطع و وصل اینترنت، و کارکرد پخش در پس‌زمینه الزامی است.
